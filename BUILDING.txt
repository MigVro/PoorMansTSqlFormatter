
This project/solution is designed to be built in Microsoft Visual Studio 2022 or 2026 Community Edition (or better),
with the "Visual Studio extension development" workload, and has a few build-time dependencies.

From the command line, use Visual Studio's MSBuild (it is not on PATH by default) and always pass /restore, as
several projects use NuGet PackageReferences:
  msbuild PoorMansTSqlFormatter.sln /restore /m /p:Configuration=Release /p:Platform=PureDotNet

Some dependencies are internal/bundled:
 - ILRepack.exe, an Apache 2.0 assembly-merging tool for post-build merging into a single assembly for command-line and demo projects
 - NDesk.Options, a command-line-option-parsing library released under a MIT/X11-style license
 - NUnit 3 and NUnit.ConsoleRunner (NuGet, restored at build time) for the tests project
 - Bridge.Net, a C#-to-JS transpiler, released under the Apache license
 - Microsoft.VisualStudio.SDK and Microsoft.VSSDK.BuildTools (NuGet, restored at build time) for Visual Studio Extensibility Package compilation

Some are additional external dependencies for different components of the solution:
 - Robert Giesecke's UnmanagedExports technique, used in the Notepad++ plugin project, may not work in some older versions of VS
 - The Winmerge plugin installer project is not supported in Express versions of Visual Studio, and requires the "Visual Studio Installer Projects" extension
 - The Winmerge Plugin requires VB6 (eg Visual Studio 6), to expose a COM object properly to WinMerge's plugin-loading framework - instructions below

The formatting library and commandline utility have been compiled under Mono (a long time ago - not recently attempted), and 
should theoretically work fine. The WinForms app, however, does not (or did not the last time I tried): the "WebBrowser" 
implementation was simply not close enough to the microsoft one for it to work. I may come back to this over the coming months/years.

The PoorMansTSqlFormatterVSPackage project produces a single 64-bit VSIX for Visual Studio 2022/2026 and SSMS 22
(bin\<Config>\PoorMansTSqlFormatterVSPackage.vsix):
 - For VS 2022/2026 you can just double-click on the VSIX file. Building the project also deploys it to the VS experimental
   instance ("devenv /rootsuffix Exp"); don't additionally install it there with VSIXInstaller.
 - For SSMS 22, install it with VSIXInstaller.exe from the SSMS install folder, eg: VSIXInstaller.exe /instanceIds:<SSMS instance id> PoorMansTSqlFormatterVSPackage.vsix
 - To remove it from SSMS 22 again, close SSMS and run Scripts\UninstallSSMS.cmd.

The WinMerge Plugin preparation is reasonably complex/painful:
 - Open a command prompt as administrator
 - Navigate to the "PoorMansTSqlFormatterWinMergePlugin" folder in the command prompt
 - Run the "Initialize_GetLibAsCOM.bat" file; this should give you a warning but succeed
 - Open the VB6 project
 - Check that the "PoorMansTSqlFormatterLib.tlb" reference does not show up as "MISSING" (if it does, review previous steps and/or remove and add the reference again)
 - In VB6, "Make" the "TSqlFormatWMPlugin.dll" file.
   - This will probably spit out an error like "Error accessing the system registry", which can be ignored, as the DLL was created (the error concerns the COM registrtion, which we will do later in the .Net setup project anyway)
 - In Visual Studio (with the Installer Projects extension), "Rebuild" the WinMerge Plugin Setup project.

The packaging and release process is currently completely manual:
 - Bump the version with VersionBump.ps1 (updates AssemblyInfo, FormatterPackage.cs and the VSIX manifest), and the WinMerge setup project version by hand
 - Rebuild solution in Release mode (with /restore), and additionally manually rebuild the WinMerge setup project
   - Setup project issues can be investigated with msiexec's verbose logging: msiexec /i PoorMansTSqlFormatterWinMergePlugin.Setup.msi /l*v MyLogFile.txt
 - Copy Binaries for simple executables, the VSIX and setup files into dedicated folders, zip them up and version-number the zip files.
 - Upload the archives to website
 - Change website to reference the new archives
 - Update Notepad++ plugin manager admin site to reflect the new version (in staging - actual live publishing is done by site administrator)

To run the tests, build PoorMansTSqlFormatterTests with /restore, then from PoorMansTSqlFormatterTest\bin\<Config> run the NUnit 3 console runner
(%USERPROFILE%\.nuget\packages\nunit.consolerunner\3.17.0\tools\nunit3-console.exe PoorMansTSqlFormatterTests.dll). The working directory matters: the test data is found via ..\..\Data.
